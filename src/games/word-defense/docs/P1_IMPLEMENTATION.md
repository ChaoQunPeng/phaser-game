# P1 战斗原型实现

本次以 `GAME_DESIGN.md` 和 `TECHNICAL_DESIGN.md` 为玩法和架构基线，不修改原始设计与 README。

## 运行与操作

项目根目录执行 `npm run dev`，打开终端给出的本地地址。合集默认进入文字塔防，也可切换回原有示例。

1. 点击底部兵种，再点击非路径空格免费部署。地图可在开始前或战斗中部署。
2. 点击「开始战斗」，经过准备倒计时自动生成测试波次。
3. 点击已部署单位查看击杀数，点击「移除选中」释放格子；单位不可移动。
4. 「暂停 / 继续」冻结或恢复战斗；失焦、隐藏自动暂停，返回后手动继续。
5. 全部三个测试波次清场且生命未耗尽则测试胜利，生命为零则失败。「重新开始」恢复就绪状态。

移动页面可上下滚动查看整个竖屏画布。游戏面板、地图、按钮、结算和特效均由 Phaser 绘制。

一套已通过模拟测试的阵容如下，坐标从 0 起算：弓 `(1,0)`、`(3,0)`、`(5,6)`，枪 `(3,2)`、`(5,2)`，骑 `(5,4)`、`(3,4)`，刀 `(2,4)`。这仅用于复现通关，不是正式关卡平衡建议。无单位防守会失败。

## 临时策略与尚未实现事项

`data/battleConfig.ts` 集中标记 placeholder：初始生命 10、路线、路径格禁止部署、攻击数值与间隔、怪物生命/速度/漏怪扣血、2.5 秒准备、三个测试波次及自动推进。固定步长 50ms 是技术测试值。

战斗策略为可替换纯函数：

- 距离暂用欧氏距离；弓 5、枪 4、刀 1、骑 3 的配置保留设计已确定值。
- 索敌暂优先沿路径进度最大的怪物，同优先级按生成顺序。
- 枪与骑暂用主目标周围一格圆形溅射，不限目标数；主目标须在单位射程内，溅射目标按主目标范围判定。
- 同一步先刷怪和移动，再攻击；抵达终点的怪物本步不再参与攻击。漏怪扣血为零时失败优先，不再将最终清场判为胜利。

这些策略均不宣称为最终玩法。金币、五槽召唤、合成、英雄、装备、技能、20 波大奖励没有在 P1 中实现；下一阶段为 P2 经营与基础合成。微信小游戏仍需实际运行环境的 Phaser 兼容性验证。

## 验证

- `npm run typecheck`：TypeScript 严格类型检查。
- `npm test`：22 个可复现核心用例，覆盖部署边界/占用/移除、路径配置、快照隔离、分段移动/漏怪、四兵种攻击、距离/溅射/策略替换、冷却、单次死亡、固定时钟、暂停、准备与波次、胜负优先级、重开，以及实际 P1 配置的胜利和失败。
- `npm run build`：类型检查及 Vite 生产构建。
- 浏览器人工交互：中文渲染、点击部署、启动战斗、自动失焦暂停、竖屏操作区、原示例与新游戏切换；控制台无错误/警告。

生产构建仍有 Vite 的大包提示：当前主包包含 Phaser，约 1.4MB（gzip 约 379KB）。不影响 Web 构建通过，后续性能与微信小游戏包体阶段需再处理。
